# 兼容与验证边界

## 当前支持

| 项目 | 当前范围 |
| --- | --- |
| 宿主 | 不设置 DSH 版本号门槛，依据实际接口兼容；Windows x64 `0.2.2-rc.1` 有真实验收，`0.2.1-rc.5` 已核对已发布源码接口 |
| 开发环境 | Node.js `>=24.9.0`，按 lockfile 安装依赖 |
| 包类型 | Mojobox 薄 Feature Pack v1，ZIP 内仅根 `pack.json` 与可选根 `icon.png` |
| 包尺寸 | 归档最多 2 MiB；清单最多 1 MiB，图标最多 512 KiB |
| 插件来源 | 可核验身份与精确版本的 npm bundle；非托管本地链接不接管 |
| 远端 | 固定 Mojobox 生产目录，无自定义来源配置 |
| 安装入口 | 已注册的 Mojobox 设置页；页面内拖拽或文件选择、远端目录预览 |

整包 `requires.dsh` 如有声明必须是合法范围；缺失或与当前内核不匹配时显示提醒，允许继续预览与选择安装。
插件 `engines.dsh` 的范围差异也只在安装器预览提示；实际产物不改写，官版宿主仍执行其兼容检查。
安装器加载不受整合包版本要求影响；不因某内核较旧、较新或尚未实测就判定其不兼容。
仅在明确的接口差异导致无法使用时限制对应功能或版本；取消版本门槛不等于所有内核均已实测。
外部插件必须声明精确 SemVer。草稿、未解决冲突、内嵌 payload、非空 overrides／presets／skills 不接受。
`builtin:` 无法确认官版映射时单项拒绝；`github:` 未完成精确产物核验，不提供通用 GitHub 安装。
插件自身的内核要求和构建脚本审批继续由官版判定，安装器不豁免。

## 版本门禁修复（0.0.1-p3.1）

旧版安装器的 `engines.dsh: "0.2.2-rc.1"` 会导致 `0.2.2-rc.3` 等后续宿主拒绝加载。
新版移除安装器自身的 DSH 版本限制，并将目录、文件预览及 npm 插件预检中的版本差异改为提醒。
修复旧内核没有 `remoteAccess.whenAccess` 时的设置页加载错误，改用已有的 `useRemoteAccess` 权限 Hook；无权限时显示说明，不挂载管理页面。
回归覆盖 `0.2.1-rc.5`、`0.2.1`、`0.2.2-rc.3` 的模拟路由注册、状态及跨版本整包预览，以及权限变化、选择确认与单项失败隔离。
仍验证归档身份、摘要、精确组件版本、冲突、依赖和配置保护；不篡改第三方版本声明。
更新安装器不会自动恢复被移除的 Profile 注册条目；需另查配置与备份，不能把范围修复当作数据恢复。

## 已有验证

2026-11-17 预构建包安装验收，使用官版 Windows `0.2.2-rc.1` 自带 CLI 与独立 `web` Profile：

- 从 `.tgz` 完成真实安装，宿主自动追加 bundle 加载项；安装时无需执行本项目源码编译。
- 重启真实官版运行时后安装器为 active，认证状态接口返回 200；浏览器打开「设置 → Mojobox」，页面加载无 JavaScript 异常。
- 重复安装后 bundle 只保留一项，Profile 中无关字段、个人配置文件与配置补丁均保留。
- 用户安装入口与网络、本地文件两种形式见[安装说明](installation.md)。此项不等于其他版本、原生桌面点击安装及完整升级矩阵均已验收。

2026-11-17 核对 npm 已发布的官版 `0.2.1-rc.5` 源码：

- `dsh` 与 `dsh-app-boot` 提供所需 `profileContext` 字段；`dsh-plugin-manager` 提供库存、核验、注册表、安装及组件管理接口。
- `dsh-client-connection` 提供同形的认证 Fetch 路由；设置模块提供 `settings.section`，`dsh-api-remote-access` 提供全局权限 Hook。
- 原版 `dsh-app-boot` 的兼容检查确认：没有 `engines.dsh` 及 DSH peer 限制时，不会按内核版本拒载安装器。核对了 `0.2.1-rc.5` 和 `0.2.2-rc.1` 的原始检查函数。

以上是已发布接口核对与源码回归，尚不属于 `0.2.1` 客户端真实启动验收。

2026-11-11 的本机隔离验收以官方 `0.2.2-rc.1` 为目标：

- 生产 npm 目标检查覆盖 33 个唯一目标，31 个安装成功并在组合或独立检查中加载，2 个被宿主兼容门禁拒绝。
- 已验证选择更新、同版本复用、保留停用状态、普通失败后独立项继续、失败项重试及更新配置保护核验。
- 已验证冲突按实际库存判定、gzip 下载长度处理、合法 npm scope 和预发布宿主范围匹配。
- 前端编译组件回归覆盖等待、防重复提交、总进度、摘要、折叠详情、新版核对与日志失败反馈。
- 官版窗口内使用受控状态／故障注入验证部分交互和渲染；日志保存调用真实宿主路由并读回 JSON。

以上为开发验收摘要，原始本机材料不包含在公开仓库或插件发行包中。
仓库自动化是可复现的源码回归，不替代真实官版业务验收。

## 尚未完成

- 原生桌面端点击安装，以及安装器跨版本升级与回退的完整验收。
- Windows 文件管理器到客户端的原生拖拽全流程，以及完整原生鼠标交互与性能专项验收。
- 其他宿主版本、操作系统及需认证私有注册表。
- 复杂插件数据迁移、全部外观设置、GPU、模型调用和登录后的业务功能。
- 每个整合包在全新依赖池上的独立完整安装矩阵。

组件管理使用官方 `setBundleEnabled` 和 `removeBundle`，只修改当前 Profile 中宿主允许管理的组件；
官方／管理组件显示保护原因。删除单个共享组件前列出受影响整合包，确认后保留历史并按真实库存显示缺项。
本次回归覆盖独立启用／暂停／删除、状态变化拒绝、共享影响、互斥、失败与重启反馈和前端交互。
实际插件删除仍需在官版客户端实测，不能将模拟宿主成功视为真实卸载成功。

不提供插件私有数据清理、完整环境迁移或自动升级内核。安装器保护其管理的安装流程与配置边界，
不承诺修复第三方旧插件、迁移插件私有数据或恢复官方内核升级造成的破坏。

## 问题归属

| 问题 | 应由谁处理 |
| --- | --- |
| 安装按钮、进度、重试、计划或日志保存异常 | [安装器仓库](https://github.com/lanyun077/Mojobox-Installer/issues) |
| 包的插件选型、版本、来源、内核或冲突声明不准确 | [Mojobox 主仓库](https://github.com/lanyun077/EAC-mojobox/issues) |
| 第三方插件业务错误、停止维护或内核适配 | 原作者；本项目改进识别与提示，必要时由主仓调整组合 |
| 官版安装、审批、加载服务自身错误 | 官方宿主；安装器保留诊断并停止不确定写入 |

即使日志经过脱敏，公开提交前仍请检查内容。不要上传完整 Profile、账号凭据或聊天记录。
